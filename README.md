# 桌面组件 v0.1

Windows 本地桌面面板。首版包含待办、周日程、倒计时。数据独立保存，暂不联动日记。

## 启动和退出

双击根目录的 **启动桌面组件.cmd**。当前机器已完成构建，正常运行不需要 Node、开发服务器或 .NET SDK。

右下角托盘图标提供：编辑布局、管理后台、刷新壁纸、切换桌面/预览窗口、打开数据目录、开机自启、退出。双击托盘图标进入/退出布局编辑。

也可以在本目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
# 普通窗口预览
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1 -Preview
```

同一个数据目录仅允许运行一个实例。日常使用从托盘退出后再更新程序。

**开机自启默认开启**，准确地说是在当前用户登录 Windows 后启动。右键托盘图标勾选/取消“开机自启”；关闭后，下次手动打开也不会重新开启。选择记录在 data/startup.json，并通过当前用户 Windows 启动文件夹的 DesktopWallpaperWidgets.lnk 生效，明确设置程序路径、参数和工作目录；不需要管理员权限。更新会迁移并移除本程序的旧 Run 启动项。测试目录与 API-only 模式不注册真实自启。启动参数 --startup 在已有实例时静默退出；桌面尚未就绪时保留托盘并每 5 秒重试。若在 Windows 设置中禁用过此启动项，请在“设置 → 应用 → 启动”中重新开启。启动记录在 .runtime/host.log。

程序与托盘使用本项目绘制的日历勾选图标，源图 assets/app.svg，多尺寸 Windows 图标 assets/app.ico。重新绘制后可运行 tools/Make-Icon.ps1 生成，再构建程序。

编辑、选图及错误提示使用程序自己的独立对话框宿主，避免桌面子窗口的弹窗把 Explorer 的桌面主窗口禁用。验证会实际打开/关闭原生编辑器，检查桌面在弹窗期间和关闭后均保持启用。

本机一次 15 秒空闲采样（3120×2080 静态壁纸、空数据、整个宿主及 WebView2 进程组）：CPU 接近 0%，7 个进程，工作集相加约 100 MB，私有提交约 271 MB。工作集包含可能重复统计的共享页，私有提交不是全部驻留物理内存；这不是压力测试或长期上限。WebView2 的低内存模式只降低空闲目标，鼠标进入卡片或主动编辑时恢复正常；常驻脚本和 API 更新仍能运行。测量原始值在 .verification/resources.json。

## 操作

- 待办：点击“添加”；点击内容编辑；点击方框完成/取消完成；× 删除；拖动 ⠿ 排序。
- 周日程：周一到周日，点击星期选择日期；‹ / › 切换周，“本周”回到今天；新增时设置内容、日期、时间；按时间排序。日期旁显示距离今天的时间，默认以周显示，点击切换天/周/月。日程右侧 ↗ 可以加入关联倒计时，✓ 表示已加入。
- 倒计时：新增名称和目标日期，或选择关联日程。点击名称编辑；点击数字切换天/周/月，独立保存每项单位。不显示小数：12 天可切为 1 周 5 天；月按实际日历月计算，显示完整月数加剩余天数，例如 1 个月 5 天。不足一周/月时直接显示剩余天数。
- 倒计时可选择“列表”或“简约”。简约样式居中显示名称、大数字和日期，悬停时显示设置与添加入口；点击数字仍切换单位。
- 关联倒计时通过 eventId 读取当前日程的名称和日期，日程编辑后同步显示，无需重复编辑。原日程删除时，倒计时保留自己原存的日期并显示“日程已删除”，可重新关联或改为独立日期。
- 每张卡片右上角 ⚙：选择“外观设置”“位置与尺寸”或“拖动布局”；也可一键切换该卡片的浅色/深色模式。各组件独立调整背景、透明度、模糊、文字色、强调色、字体、字号和圆角，颜色可用选择器或 #RRGGBB。今天的星期使用强调色突出。
- 文字粗细可用滑块调整 100–900，倒计时的数字粗细独立调整，默认 600；同样支持即时预览与保存。实际字重取决于所选字体支持的字重。
- 卡片和网页设置面板不显示滚动条，内容较多仍可用滚轮或键盘查看。卡片宽度不再强制至少 260 像素，可缩窄或一直拉宽到屏幕边缘；只保留 80 像素的操作下限与屏幕边界。
- 背景选择“颜色／图片／无”，效果单独选择“毛玻璃／无模糊”。透明度、模糊强度、字号、圆角使用滑块，拖动立即预览；保存才写入，取消恢复原外观。浏览器编辑器上方固定显示预览；Windows 编辑窗口旁的实际桌面卡片实时变化。
- 背景透明度 100% 或选择“无”时隐藏背景，文字仍可见。图片只通过原生程序选择，会复制到 assets/backgrounds/。第一次使用图片背景时选图；已有图片时调整透明度、效果或切换背景会保留图片，通过齿轮菜单“更换背景图片”主动换图。
- 布局编辑：拖动标题区域改变位置，拖动右下角调整尺寸，点击“保存并退出”；“位置与尺寸”可直接输入数值。尺寸与坐标使用当前屏幕的逻辑像素，保存时位置转为比例并记录参考尺寸。分辨率或缩放变化时卡片尺寸随可用空间缩放，比例变化导致重叠时临时重新排布，原有配置保留。主动编辑同一屏幕上的布局时仍允许手动重叠。
- 组件区域与桌面图标重叠时，组件接收点击，请把组件放在图标空白处。组件外的区域通过原生窗口裁剪交还桌面。
- 新增/编辑主动打开 Windows 输入窗口；常驻组件不安装全局键盘或鼠标钩子。

## 外接屏和壁纸

组件始终仅显示在 Windows 当前主屏。接入或拔出外接屏、切换主屏、修改分辨率时重新适配，不在副屏重复显示；忽略旧配置中的固定 monitor 选择。位置按可用空间的比例保存，卡片尺寸相对保存时的逻辑分辨率缩放，字体按 Windows DPI 显示。不同主屏保留各自的布局；重新连接原屏幕可恢复原布局。布局暂以 Windows 显示屏名称保存，尚未升级为硬件标识；第一次成为主屏的屏幕使用适合其比例的默认布局。

首版读取 Windows **静态壁纸**并缓存其按屏幕位置显示的图像。卡片透明和毛玻璃是网页对缓存壁纸的合成效果，**不是 TranslucentTB 的系统实时 Acrylic**。缓存只在启动、屏幕变化、桌面设置变化或手动刷新时生成，不持续截图。动态壁纸与第三方壁纸引擎不在首版验收范围。

## 数据与备份

```text
data/
  todos.json         # 待办及完成状态、顺序
  events.json        # 日程日期和时间
  countdowns.json    # 目标日期
  layout.json        # 屏幕布局与各组件外观
  api.json           # 本机接口开关、端口及访问密钥（不是 LLM API Key）
  startup.json       # 托盘自启选择（由程序单独管理，不开放给数据 API）
assets/backgrounds/  # 自定义图片
.runtime/            # WebView2 缓存、壁纸缓存、日志
```

JSON 使用 UTF-8，可人工查看。相应数据文件在首次保存时生成。退出程序后备份 data/ 和 assets/backgrounds/ 即可。编辑 JSON 后重启读取。

每次写入采用临时文件和原子替换，保留上一次的 `.json.bak`。JSON 无法解析时，存在可读备份则恢复并保留 `.damaged-时间` 原件；没有可读备份则停止启动，避免覆盖源文件。备份仅是上一版，不代替历史备份。

## 构建与验证

使用 Windows 自带 .NET Framework 4.8 编译器，不额外安装 SDK。唯一新增代码依赖是 Microsoft.Web.WebView2 **1.0.4258.31**（用于嵌入网页），通过官方 NuGet 获取，依赖保存在 .dependencies/。使用系统已有 Evergreen WebView2 Runtime。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
node --test tests/*.test.mjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify.ps1
```

依赖不在时 build.ps1 会下载；本机配置了本地代理时优先使用代理。PowerShell 脚本包含 UTF-8 BOM，兼容 Windows PowerShell 5.1。

验证数据全部在 .verification/，不会读写日常 data/。浏览器开发预览可运行 `node tools/preview.mjs`，地址 http://127.0.0.1:18876，预览数据仅在浏览器 localStorage 中，与正式 JSON 不互通。正式桌面 UI 通过本地文件映射加载，后台与 API 由同一个 C# 宿主在 127.0.0.1:18877 提供，不需要 Node 服务。

## 管理后台和未来 AI 接入

从托盘点击“管理后台”，通过一次性入口自动进入。也可访问 http://127.0.0.1:18877/admin.html，输入 data/api.json 中的 token。后台支持待办、日程、倒计时的新增、编辑、完成和删除；修改会立即更新桌面。多个后台页面之间需要点击“刷新”获取最新内容。

选择“接口”可查看本机接口地址与访问密钥。当前仅开放本机 CRUD 接口，没有 LLM 调用、LLM API Key 输入或日记访问。未来可让模型用工具调用这些接口；JSON 仍是可读数据源，接口负责校验和防止旧版本覆盖。字段和调用示例见 API.md。

退出程序后可在 data/api.json 修改 port 或 enabled，重新启动生效。禁用接口不影响桌面文件保存。备份中如果包含 api.json，请将其视为带有本机访问密钥的私人文件。

## 后续开发组件

组件位于 `ui/widgets/`；现有三个模块各自负责显示和操作。公共样式在 `ui/styles.css`，日期和布局工具在 `ui/core.js`，宿主消息在 `ui/bridge.js`。

增加新组件时，让 AI 参考现有模块的 `createTodo(api)`：通过 `api.card` 创建卡片，通过 `api.edit` 请求原生编辑窗口，通过 `api.change` 修改并保存数据。涉及新数据文件时，需要同时加入 host/Store.cs 的文件白名单与字段校验。UI 不直接读取任意本地路径。

不需要插件 SDK；先增加一个模块并在 app.js 注册。日记联动待数据管理方式确定后再设计。

## 验证边界

已验证：构建；日期边界与日程排序；待办排序；多个逻辑分辨率的布局边界及初始布局不相互遮挡；原生桌面父窗口关系、可见状态和区域裁剪；真实 JSON 保存、备份恢复、程序重启后的数据与外观恢复；浏览器中的新增、勾选、周日程、倒计时、外观、拖动/缩放及刷新恢复；原生输入窗口打开/取消和高 DPI 标签布局；后台新增与完成待办、新增日程；API 鉴权、来源限制、字段检查、并发写入、冲突拒绝和重启持久化；API 到真实 WebView2 组件的更新与一次性后台会话认证。

仍需设备验收：当前只连接一块屏幕，**真实外接屏热插拔、混合 DPI、Win+D、桌面图标拖动与右键菜单、真实中文拼音输入法** 尚未逐项完成人工验证。Windows 11 的桌面宿主行为可能随系统版本变化。

Windows 自动化技能明确禁止使用 Windows 键及相关快捷键，因此此次没有自动按 Win+D。请手动验证：按 Win+D 后卡片仍在桌面；其他软件正常遮住卡片；桌面空白处和卡片上右键可显示桌面菜单；中文输入只在主动编辑时进入输入框。

开源研究与模型分工见 DEVELOPMENT.md 和 MODEL-WORKFLOW.md。
